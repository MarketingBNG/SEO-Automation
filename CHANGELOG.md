# Changelog

What changed in the dashboard, newest first. Claude Code adds a line with every change pushed to
`main`. Format: `- (part) what changed and what it means for the work`, where the part is the one it
affects most: writer, fact-check, ops, seo, publisher, social.

## 2026-11-22
- (ops) SEB one-time device enrollment: the first code links an employee to their Windows user on that device and stores a revocable credential securely in Windows; each later launch/reboot exchanges it silently for a fresh SEB session, so a code is asked again only if the enrollment is revoked, the credential is wrong, or a different Windows user signs in. The daily Check In button records the Zoho People punch and reuses today's confirmed punch after a restart. Admins can list/revoke enrollments.
- (ops) SEB on a no-training day (e.g. Sunday) now quits to the desktop automatically: /seb reads the gate, sees no training, and navigates to the configured SEB quit URL. This is read-only, so it does not mark training complete and does not trigger the Finished timesheet sync; the Finished flow is unchanged.
- (ops) SEB training pilot (dashboard side): a training-only page at /seb for Safe Exam Browser, entered with a short-lived single-use code minted in the signed-in regular browser (/seb-code) — Google sign-in and the main dashboard stay in the regular browser, no secret in URLs. After Check In it shows that IST day's assigned lesson or test and, on Finish, triggers the configured quit link only after the server saves and confirms completion.
- (ops) Zoho People Check In: each employee connects their own Zoho People once; the dashboard records an idempotent attendance punch (one per IST day, safe on double-click/restart/retry, reconciles an uncertain outcome before retrying). Checkout stays manual in Zoho. Needs ZOHO_PEOPLE_REDIRECT_URI and the Zoho People attendance API scope/plan (shown to the admin on the connect status).
- (ops) On confirmed Finished, the person's prior worked days are queued for Zoho Projects timesheet sync and posted under each day's own IST date to the team project's General task (idempotent, backfills, skips no-work days); the queue drains from a cron and never blocks SEB exit or desktop access.
- (ops) A regular test now covers the lessons since that person's last test (any kind), instead of a fixed 8-day window, so the per-person random test days are always covered. A lesson is still only tested once. Every week stays at 4 lessons and 2 tests (6 working days, Sunday off).
- (ops) The monthly test is labelled "Brain Test" on the dashboard, and the admin/manager training report now shows each person's test dates for the week (the employee never sees their own upcoming test dates).
- (ops) In the month-end grand-test week, a person now gets one normal weekly test plus the grand test, so that week still has exactly two tests (not two normal plus the grand). The grand day is neither a normal test day nor a lesson day.
- (ops) Training rhythm: two tests a week per person. Week 1 is Wednesday and Saturday; from week 2 each person gets two UNANNOUNCED test days a week (not the same day for everyone, not a fixed day), with lessons on the other working days. A day is a lesson or a test, never both. Sunday stays off. Added a monthly GRAND test on the last Tuesday of the month (from training_grand_start, default next month): a bigger test on everything learned so far, and that day has no lesson or weekly test. Schedule off still means a lesson and a test every day.
- (ops) Device lock gate now tells apart, when the laptop is not locked: training done, training expected today but not generated yet (not-ready), and no training scheduled today (no-training, e.g. Sunday). "Done" is reported only when the day's training is available and complete; a not-yet-generated lesson no longer looks completed. The lock flag is unchanged.
- (ops) Daily training is now generated at 08:00 IST, one hour before the 09:00 device lock window, so a trainee's lesson and test are ready before their laptop locks (earlier it generated at 09:00, the same time the lock opened, so the lock could fail open until generation finished).
- (ops) Device lock gate now reports a clear status (done, pending, invalid-token, before-window, not-tracked, error) alongside the lock flag. A backend failure is reported as "error" and no longer looks like a real training completion; the laptop still fails open. No change to what the device reads (the lock flag).

## 2026-11-21
- (ops) Consent screen v2: the monitoring terms now state the lesson lock plainly (during work hours the company laptop stays on the training screen until the day's lesson/test is finished, then unlocks for the day; Sundays and holidays have none). The version bump means everyone re-accepts the clearer terms. device/uic-lock.ps1 enforces it on the device with an admin-password backup; it is a disclosed, company-device kiosk.
- (ops) Device lock gate: the laptop watcher can now ask the dashboard (GET /api/worklog/gate with the person's work token) whether today's training is done. It locks only from 09:00 IST, and once the lesson/test is done it stays unlocked for the rest of the day (a reboot does not re-lock). device/uic-gate.ps1 polls this and holds a reversible Edge kiosk on the dashboard while locked, freeing the laptop when done. The admin is never locked; it fails open on a network error.
- (ops) Zoho Projects timesheet: everyone except the admin gets a one-time "Connect Zoho" banner; after connecting, their day's attendance hours (first watcher report to last) are logged to their team's project General task. Marketing goes to Marketing_SGS_Zoho, Automation to its project. The Work time report gets an admin "Log to Zoho" button per person for a day; app-level detail stays in the dashboard. The employee does nothing beyond the one-time connect. Needs ZOHO_PROJECTS_REDIRECT_URI set and that redirect URL registered on the Zoho app.
- (ops) Team Training: the top-level "Videos" library tab is removed; the section is Read lessons and the Game.
- (ops) Team Training lesson view: the "Watch" (slides and videos) tab is removed; each lesson now has Read and a Game only. The game is always available for practice and understanding the lesson (the "submit the test first" message is gone).
- (ops) Team Training, the person's own view: they no longer see any results (no score, answer review, results list or level history); only the admin and managers see those. While a test is open, lessons and notes are hidden so they answer from memory; outside a test they can re-read today's and earlier lessons, each with a short "Quick notes" summary. After submitting they see a thank-you, not the score.
- (ops) AI credits page shows team-training lessons and test grading as their own cost lines (split from the writing-skill refresh), so you can see what the AI grading of typed answers costs.
- (ops) Training schedule: Monday and Tuesday lessons, Wednesday a test on them, Thursday and Friday lessons, Saturday a test on them, Sunday off. A test covers all the untested lessons since the last test. The first week is lessons only (no test); surprise tests begin the week after. Starts 2026-11-23; set training_pattern_start to empty for a lesson and test every day instead.
- (ops) Tests now have typed (written-answer) questions as well as multiple choice. The AI grades each typed answer (0, 0.5 or 1 with a one-line reason, noting spelling or grammar), added to the score. Keystrokes, backspaces and time are tracked; the admin and managers see the typed answer, the AI score and these stats. Typed answers start from the first test. Each typed answer uses one AI call to grade.
- (writer) Training lessons now cover the Indian forms Form 16/16A, Form 13, Form 10F/TRC and Form 26AS/AIS, and every technical lesson includes a worked example.
- (ops) Team Training groups people by team (Marketing or Automation; set it in Team & Roles). A manager now sees the training report, person pages and finished tests of their own team only; the admin still sees everyone.
- (ops) Team Training report shows the admin and managers how long each lesson and test took, the full trail of answers picked and changed, and AI-use flags (pastes, tab-switches, time away) with a red "check" mark on a suspicious test. A person does not see these about their own test.
- (ops) The admin (on anyone) and a manager (on their team) can add remarks on a person's training; each remark saves their level, recent average and whether they moved up that week. The person does not see them.
- (ops) A "Live now" panel shows the admin and managers the tests being taken right now, refreshing every few seconds, with each person's current answers. The person taking the test does not see it.
- (ops) Everyone except the admin accepts a one-time monitoring-terms screen before using the dashboard (attendance, work activity for the timesheet with no screenshots or keystrokes, training review, visible to the employer). Their acceptance is recorded with name, version and date; it shows once per person.
- (ops) Groundwork for the per-task timesheet: each person's current task and the blocks of active time behind it are stored, and a per-person token lets the device activity watcher report time. The Zoho Projects connection, the task picker and the watcher itself are not live yet.

## 2026-11-19

- (publisher) Blog covers made without a photo: a long title is made smaller so it never runs into the "By author" line.
